# docs-site — what is real, and what is a placeholder

This file exists so nobody has to guess. Every page in this site renders, every
control works, and every claim the shell makes about itself is enforced by a
test. But the *content* is thin on purpose: this stage built the frame, and the
stage that writes the documentation fills it.

Read it before adding a page.

## What is real

**The shell.** Header, sidebar, mobile drawer, the partial scrim, the settings
panel, the effect layers, search. All of it is measured rather than asserted —
see "Verified" below, including that each frosted surface actually *samples*
rather than merely declaring `backdrop-filter`.

**The theme runtime.** All thirty-nine palettes, three modes, two typefaces,
three glass levels, four corner presets, four background patterns, the aurora,
the grain and ambient motion. Every one of them is generated from
`spec/theme.toml`; nothing on this site writes a setting name down.

**Scoped themes.** `/scoped-themes` is not a demonstration built for the page —
it is two real `ThemeScope` components with the same controls the page header
has. That page is the reason the rest of this stage exists.

**Both locales, plus a third.** English, Portuguese, and a generated
pseudo-locale at `/qps/` that brackets and lengthens every string. Open it at
320 px: anything that is not bracketed was hard-coded and never went through the
catalogue, and anything that overflows only fitted because English is short.

## What is a placeholder

**Depth of prose.** Every page now explains what it documents and demonstrates
it, in both locales. What they are not yet is *reference* documentation — there
is no per-component page, no prop-by-prop table beyond `ThemeScope`, and no
guidance on when to reach for one component over another.

**CJK is shipped whole, not sliced.** Noto Sans SC alone is 7.1 MB. It is never
preloaded and its `unicode-range` means a Latin page fetches none of it, which a
test asserts — but a reader who opens the typography page in a poor connection
waits for it. Google Fonts solves this by slicing each CJK family into about a
hundred range-limited files. Doing the same here is a change to the face table's
shape, not to any component, and is worth doing before this ships publicly.

**The component page template — half of it.** `/components` generates its prop
table from the theme model, so a documented prop cannot disagree with the
implemented one. What it does not yet do is read `spec/components/<name>.toml`,
because no component has one: `ThemeScope`'s props **are** the scopable settings,
and a second file listing them could only disagree. The template takes its final
shape with the first component that needs a contract of its own — Stage 6.

That is the whole list. Everything else below is real.

## Also real

**The React path is live.** Switching an example to React `import()`s a bundle
that is **not requested on a normal page view** — measured: zero resource entries
before the toggle, one after. It mounts the generated React `ThemeScope` into the
same stage, and that component stamps `data-palette="violet-vivid"`
`data-theme="dark"` — byte-identical to what the Dioxus half server-rendered.
That is prop-surface parity *demonstrated* rather than asserted, which is the
only version of the claim worth making.

**The code panel shows derived source.** The Dioxus and React snippets are
generated by `pages::snippet` from the same `ScopeRequest` that built the example
above them. A hand-written snippet drifts on the first edit and the reader cannot
tell which one lied.

**Search covers the system's own names.** Tokens, props and all thirty-nine
palettes, each pointing at the page that explains it, built from the generated
crates so an upstream addition is searchable without an edit here. Page rows and
name rows behave differently on an empty query, which is deliberate: showing
thirty-nine palettes under an empty search box would bury the navigation.

## How it is built

```sh
cargo xtask docs      # writes docs-site/dist/
pnpm --filter @noctua-world/docs-site run build:example   # rebuilds the React bundle
```

`cargo xtask docs` is an ordinary Rust binary. No `dx`, no wasm toolchain, no
JavaScript runtime — it renders `rsx!` to a string with `dioxus-ssr`. The output
is static files any server can serve, and `docs-site/dist/` is **not** committed:
about 5 MB of copied palette stylesheets, all reproducible from sources that are.

The React bundle is **optional**. `cargo xtask docs` notes its absence and
carries on, because the Rust half of this repository owes nothing to Node
(`NOCTUA.md §9.11`) and a site that would not build without `pnpm install` would
break that. Without it the implementation switch reports a failed load and the
server-rendered Dioxus example keeps working.

The page is correct before any script runs. `assets/shell.js` adds the settings
to a complete page; it never constructs one.

## Verified, in a real browser

**49 Playwright specs**, run against the built site by
`cargo xtask docs --verify`. Not a list of things somebody once checked: a suite
that fails the build.

```sh
cargo xtask docs --verify     # build the site, then run all 49
pnpm run test:browser         # the suite alone
```

It uses the system's Chrome (`NOCTUA_CHROME` overrides the path) rather than
Playwright's download, which cannot find its libraries on a Nix system and exits
before Playwright can say why.

Every colour in the suite is read from **screenshot pixels** decoded in a canvas,
never from `getComputedStyle` — the same rule the `colour_read_from_dom` gate
imposes on the shell. The two places that read a serialised colour do so only to
paint it, and carry an `allow-literal` saying so.

## Five bugs this stage found and fixed

All five were silent, which is why they are written down.

**`hidden` hid nothing.** The browser's `[hidden] { display: none }` is a
*user-agent* rule, so any author rule outranks it — including `.nd-scope
{ display: flex }` and `.nd-found a { display: block }`. Every `hidden` in the
shell was inert: the React example stayed visible behind its replacement and the
search results showed before anything was typed. The JavaScript setting the
attribute was correct in both cases. One `[hidden] { display: none !important }`
fixes it, and it is the only `!important` in the stylesheet.

**Every border inside a themed component was the page's colour.** The shell
declared `--nd-edge: <hairline> solid var(--nc-color-border)` at `:root` — the
obvious convenience, and a bug, because a `var()` resolves where it is
*declared*. Every element reading `--nd-edge` drew the root's border colour,
including elements inside a `ThemeScope` on a different palette in a different
mode. Nothing errored, every token still resolved, and the result merely looked
slightly off. The `frozen_colour_indirection` gate now catches it; the shell
names its border colour at each point of use, and the repetition is the point.

Measured after the fix, by painting into a canvas rather than comparing
serialised strings: page border `[85,84,83]`, light azure component
`[195,192,190]`, nested dark rose `[85,84,83]` — each sitting one step from *its
own* surface. Before the fix all three were identical.

**The gates walked `node_modules` through a symlink.** `SKIP` matched
`node_modules` only at the repository root. The moment `docs-site` became a
second pnpm workspace package, `docs-site/node_modules` appeared and the gates
began reporting hundreds of findings inside the vendored colour output — a file
this repository is forbidden to edit. Those three directory names are now matched
at any depth.

**Glass was never applied on a first visit.** Every glass block was a bare
attribute selector — which is what makes glass scopable — so until a reader
changed the setting, nothing matched, `--noctua-glass-blur` was undefined, and
`backdrop-filter: blur(var(--noctua-glass-blur))` was invalid at computed-value
time. An invalid `backdrop-filter` is `none`. Every frosted surface in the system
rendered flat and nothing reported it. The default level is now also declared at
`:where(:root)`, and a test asserts it.

**Three `max-width` media queries.** Written by the same file whose header says
breakpoints are minimum-width only. The gates did not catch it because media
preludes were unchecked. They are now: `max-width` is rejected outright, and a
`min-width` must equal a breakpoint declared in `spec/tokens.toml`.
