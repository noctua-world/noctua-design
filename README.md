# noctua-design

The Noctua design system: tokens and components, as **two packages that behave
identically** — a Dioxus crate and a React package — plus a documentation site.

## Before you clone

Clone this **only** inside `noctua-workspace/repos/`, and start your agents
**only** from the workspace root:

```sh
cd path/to/noctua-workspace   # the directory holding the .noctua-workspace marker
git clone <this repository> repos/noctua-design
claude                       # from here — never from inside the repository
```

Anywhere else, this repository cannot reach the shared documents or its sibling
`noctua-colors`, whose output it vendors. An agent started inside it cannot read
either, and guesses instead of looking; it detects that itself and prints a loud
warning, so if you see one, close it and reopen it at the workspace root.

## Quick start

Requires only a Rust toolchain, and nothing to install first: the `cargo xtask`
alias ships in `.cargo/config.toml`, and the WebAssembly target is declared in
`rust-toolchain.toml`.

```sh
cargo xtask check     # validate spec/, run every gate, check the generated output
cargo xtask build     # compile spec/ into tokens, icons and dist/
cargo xtask dev       # ...and serve the docs site, rebuilding as sources change
```

`cargo xtask check` also runs formatting, lints and tests, and is the same
command CI runs.

**Node is optional.** It is needed only for the React package and the browser
suite. The Rust half of this repository builds and tests without it, and
`cargo xtask check` proves that rather than assuming it.

## What is here

| Path | What it is |
|---|---|
| `spec/` | The source of truth: tokens, theme, icons, syntax, i18n, and one contract per component. **The only files you edit** to change any of them |
| `crates/noctua-design/` | The Dioxus package |
| `packages/react/` | The React package |
| `crates/noctua-design-tokens/`, `packages/tokens/` | **Generated** from `spec/`, and committed |
| `packages/tokens/vendor/` | The colour tokens, **generated by `noctua-colors`**. Never edited here |
| `assets/fonts/` | The subset fonts, their licences, and a reproducible attribution |
| `crates/noctua-design-styles/` | The component rules, hand-written. `sources()` is the order they load in |
| `dist/` | **Generated, committed**: the CSS layers, `components.css`, the behaviour modules and their manifests |
| `crates/noctua-design-dist/`, `packages/dist/` | **Generated**: `dist/` copied, because a registry cannot carry a file above a package |
| `examples/` | Two consumers from outside the workspace, and [what each proves](examples/README.md) |
| `docs-site/` | The documentation site, and [its own README](docs-site/README.md) |

Generated directories are committed so every consumer works with no build step.
`cargo xtask check` fails if one drifts from `spec/`.


## Use it in your own project

**There is no build step.** No Tailwind, no bundler, no preprocessor: the
stylesheets and the behaviour modules are generated, committed, and linked.

### The files, and where they go

Three directories from this repository become one static directory of yours —
or, if you installed from a registry, `noctua-design-dist` is the first of them
and writes itself out:

| From | To | What it is |
|---|---|---|
| `dist/` | `<static>/` | the stylesheets, the behaviour modules, and the palette and theme data they read |
| `packages/tokens/vendor/css/` | `<static>/tokens/css/` | the colour tokens, from `noctua-colors` |
| `assets/fonts/` | `<static>/assets/fonts/` | the faces `fonts.css` asks for — copy the ones you use |

`dist/fonts.css` reaches its faces at `../assets/fonts/…`, so `dist/` and
`assets/` stay siblings. Nothing else in `dist/` looks outside itself.

### The links, in the one order that works

`dist/base.html` is the list, generated, and it is the file to copy from rather
than the paragraph to retype. It ends with `components.css`, and **the order is
load-bearing**: the default palette has to precede anything that could tie with
it, and the component rules come last so your own stylesheet — linked after
them — wins.

**Run `dist/bootstrap.html` too.** It is an inline script that stamps the theme
attributes before the first paint. Link the sheets without it and the page has
no palette at all, because this system's default palette is scope-anchored.

### The components

A Rust consumer adds the crate; a JavaScript consumer adds the package. Both
also add the one that carries the files above, because neither registry will
package a file above the package directory:

```toml
# Cargo.toml
noctua-design = "0.1.0"

[build-dependencies]
noctua-design-dist = "0.1.0"   # then: noctua_design_dist::write_to("static/dist")
```

```json
"@noctua-world/design-react": "^0.1.0",
"@noctua-world/design-dist": "^0.1.0"
```

The git-tag form works too, and is what a project inside this workspace uses
while it is edited alongside the system:

```toml
noctua-design = { git = "https://github.com/noctua-world/noctua-design", tag = "v0.1.0" }
```

`examples/consumer-rust/` and `examples/consumer-web/` are both of those,
working, from outside this workspace. Start there.

### The behaviour

Every module in `dist/` is an ES module a page imports directly:

```html
<script type="module">
  import { enhanceTabs } from "./dist/tabs.js";
  import { enhanceRoving } from "./dist/roving.js";
  enhanceTabs();
  enhanceRoving();
</script>
```

Import the two or three your markup needs; nothing pulls in the rest. Each
module exports `enhanceX(root)` and `releaseX(root)`. A page with a client-side
router calls the second one before it replaces markup — a behaviour that cannot
be released is a defect for every consumer with a router.

### Switching from a path dependency to a tag

`noctua-central` develops against `path = "../noctua-design/crates/noctua-design"`
(`NOCTUA.md §8.6`). Three lines change when it moves to a tag, and nothing else:

1. `Cargo.toml` — the `path` becomes `git` + `tag`, as above.
2. `package.json` — the `workspace:*` becomes the `github:` form, as above.
3. Wherever the app copies `dist/` into its own static directory, the source
   becomes the checkout Cargo made rather than the sibling working tree.
